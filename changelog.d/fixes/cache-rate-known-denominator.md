- **fix(cache):** the Prompt Cache dashboard no longer blanks Cache Rate and Cache Reuse Ratio to `N/A` when a single request never reported a cache counter. Since #20271 the writer stores `NULL` (unknown) instead of a measured `0`, and the completeness rule `COUNT(tokens_cache_read) = COUNT(*)` demoted the whole aggregate — on a 260k-request install, 99 unknown rows hid a 92% reuse ratio. Each rate is now computed over the rows that did report, the same rows feed the per-provider table and the 24h trend, and the existing "Some usage has unknown provenance" caveat stays next to the value. Cache Rate is a **cache-read hit rate**: `read > 0` over the requests that reported `cache_read` (a write-only row has no read evidence either way, so it leaves both terms). That is narrower than the previous "any cache activity" count (`read > 0 OR write > 0`) and the numbers move accordingly — on the same install claude reports 95.2% (89,466 read hits / 93,975 requests that reported a read) instead of the 97.5% activity share. Only a provider that starts reporting `cache_read` widens the denominator; `cache_creation` never does. `getCacheMetrics`/`getCacheTrend` expose the known-subset denominators (`requestsWithKnownCacheRead`, `inputTokensWithKnownCacheRead`); the completeness flags keep their meaning.
