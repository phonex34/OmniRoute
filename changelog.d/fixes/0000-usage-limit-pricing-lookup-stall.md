- **fix(usage):** API keys with a daily/weekly USD usage limit no longer pin a CPU core. The limit check runs before every `/v1` request and re-priced every request in the key's daily and weekly windows each time (one pricing lookup per request; ~11k per check on a key with ~9k requests a week). Each request is now priced once, its cost cached on its `usage_history` row (`limit_cost_usd`/`limit_cost_status`, migration 214a — fork migrations take the latest upstream number plus a letter so they never collide with upstream's next slot), and the check sums the cached costs over a covering index, pricing only requests added since the last check; both windows are read in one pass and each (provider, model) pricing row is resolved once per check. Spend totals are unchanged; a check on a ~9k-request week drops from ~125 ms to ~1 ms. Behaviour change: a counted request keeps the price it was first priced at, so a pricing edit applies to later requests only. Requests with no pricing row are still re-tried on every check, so adding the missing price reopens a window that failed closed on them (#12341).
